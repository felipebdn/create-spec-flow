# archive

Changes that are finished and verified, moved out of the active queue.

Nothing here is deleted. An archived change remains the explanation of why the code is the way it is
— the material the next person (or the next agent session) reads when they ask "why did they do it
this way?".

An archived change describes the code **at the moment it was written**. Never read a folder here as
the current state of the system; for that, read the code and `.specs/memory/`.

Archiving is done by the `spec-archive-change` skill, on an explicit decision by the user — never
automatically by `RUN-ALL.md`.
